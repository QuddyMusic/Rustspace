# Аудит безопасности

*English version: [SECURITY-AUDIT.md](SECURITY-AUDIT.md).*

Этот проход — клиент (`bs-api`, `bs-ws`, `bs-identity`, `bs-media`, `bs-voice`, `bs-app`) и его
зависимости. Раздел о сервере дополняется по мере написания сервера на Rust.

## Клиент — исправлено

| № | Важность | Что найдено | Что сделано |
|---|----------|-------------|-------------|
| C1 | Средняя | Ссылки, которые присылает инстанс (исходный код, страница релиза, всё, что рисуется гиперссылкой), без проверки отдавались системе. Система открывает любую схему — `file:`, `smb:`, обработчики приложений, — и чужой или взломанный инстанс мог запустить их одним щелчком. | Единая застава в конце каждого кадра выбрасывает любое открытие ссылки, кроме `http(s)://` с именем узла и без логина (`app::safe_link`), откуда бы оно ни пришло. |
| C2 | Средняя | Адрес LiveKit приходит от инстанса и использовался как есть: инстанс, открытый по `https`, мог увести звонок на открытый `ws://`. | `ws://` принимается только для loopback или когда сам инстанс открыт по `http://` (пользователь это уже разрешил); иначе звонок отклоняется с сообщением. |
| C3 | Низкая | Зависимости с исправленными уязвимостями: `lru` (RUSTSEC-2026-0253), `rustix` (RUSTSEC-2026-0486); отозванные `async-executor`, `clipboard-win`. | Обновлены в `Cargo.lock`. |

## Клиент — проверено, менять не нужно

- **Токены.** Домашний токен лежит в системном хранилище ключей; запасной файл и хранилище
  токенов федерации пишутся атомарно с правами `0600` и `create_new`; секреты затираются в
  памяти и не попадают в логи.
- **Транспорт.** Только `https`/`wss`, пока пользователь явно не разрешил открытый текст для
  инстанса; редиректы в клиенте API выключены; кадры и сообщения WebSocket ограничены по размеру.
- **Куда уходят токены.** У каждого инстанса свой клиент и свой токен; запросы файлов идут без
  токена; абсолютные адреса файлов — только того же источника; внешние картинки — только с
  разрешённых GIF-хостов по `https`, редиректы проверяются.
- **Файлы.** Из имён при скачивании убираются каталоги и служебные символы; загрузки и
  изображения проходят лимиты размера и разрешения до декодирования (`bs-media::Limits`).
- **Содержимое сообщений.** Markdown превращает в ссылки только `http(s)://`; HTML не рисуется.
- **Обновления.** Проверка только читает API GitHub по TLS и открывает браузер; сама ничего не
  скачивает и не запускает.
- **Unsafe.** Запрещён во всём воркспейсе (`forbid` в `bs-voice`).

## Клиент — принято или открыто

- `quick-xml` 0.38 (RUSTSEC-2026-0194/0195, отказ в обслуживании на враждебном XML) приходит
  из `syntect`/`plist` и `zbus_xml`. Разбирает только данные, вшитые в сборку, не сетевой ввод.
  Ждём обновления зависимостей.
- `glib` 0.18 (RUSTSEC-2024-0429, некорректный `VariantStrIter`) приходит с GTK 3 для трея.
  Затронутый итератор не используется. Уйдёт с переходом трея на GTK 4.
- Неподдерживаемые транзитивные крейты (`bincode`, `paste`, `proc-macro-error`, `ttf-parser`,
  `yaml-rust`, `zvariant` 4): известных уязвимостей нет; отслеживаются через `cargo audit`.
- Недокачанный файл пишется рядом с целью как `<имя>.part`; в общедоступной папке другой
  локальный пользователь мог бы создать его заранее. Риск низкий, не менялось.
- Имена и текст ссылок показываются как присланы, включая управляющие символы направления
  Unicode. Полный адрес всегда виден в подсказке; очистка запланирована вместе с серверной
  проверкой.

## Сервер

Сервер на Rust (`bs-server`) пишется по коду оригинального сервера, поэтому каждая часть
оригинала проверяется по мере переноса. Найденное на сегодня (конфигурация, хранение,
регистрация, вход, токены):

| № | Важность | Что в оригинале | В сервере на Rust |
|---|----------|-----------------|-------------------|
| S1 | Низкая | На неизвестное имя вход отвечает до хеширования пароля, и по времени ответа видно, существует ли имя. | bcrypt считается всегда (для несуществующего пользователя — по холостому хешу); по времени случаи не различить. |
| S2 | Низкая | Необработанные исключения отдаются с текстом (поведение Fastify по умолчанию), а в нём бывают SQL и пути. | Внутренние ошибки пишутся в лог, наружу — фиксированный ответ. |
| S3 | Низкая | Идентификаторы-снежинки идут за системными часами: если их перевести назад, идентификаторы пойдут назад и могут повториться. | Генератор не возвращается во времени: идентификаторы остаются возрастающими и уникальными. |
| S4 | Инфо | Для удалённого аккаунта ответ `account_deleted` приходит при любом пароле и выдаёт, что аккаунт существовал. | Оставлено ради совместимости (клиенты показывают особое сообщение); время ответа выровнено. |
| S5 | Инфо | bcrypt учитывает только первые 72 байта пароля. | Формат сохранён намеренно: хеши взаимозаменяемы с оригиналом. |
| S6 | Высокая | Токен LiveKit и `voice_join` проверяли только `CONNECT`. Приватный канал закрывается запретом `VIEW_CHANNEL`, а `CONNECT` у участника остаётся — он получал токен скрытой голосовой комнаты и мог её слушать. | Исправлено: нужны оба права; при потере доступа участник отключается от комнаты. |
| S7 | Средняя | Получатель заявки в друзья мог ответить на неё повторно: статус не проверялся. Принятая когда-то заявка «принималась» снова и возвращала дружбу, которую другая сторона разорвала (а с ней — право добавлять в группы и слать приглашения). | Исправлено: ответить можно только на ожидающую заявку. |
| S8 | Средняя | Исключённый или вышедший участник сохранял строки ролей и личные переопределения прав; вернувшись по приглашению, получал их обратно, включая модераторские. | Исправлено: роли и личные переопределения снимаются вместе с членством. |
| S9 | Средняя | Автор мог править свои сообщения после исключения или бана: проверялось только авторство. Забаненный переписывал старые сообщения в пространстве, куда ему закрыт вход. | Исправлено: правка требует, чтобы автор по-прежнему видел канал. |
| S10 | Средняя | Исключённый или забаненный оставался подписан на события пространства до переподключения: изменения участников, ролей, настроек. | Исправлено: подписка снимается сразу после `member_left`. |
| S11 | Средняя | События голоса (`voice_state_update`, статусы, отключение микрофона модератором) рассылались всему пространству, и по ним было видно, кто и когда сидит в скрытом канале. | Исправлено: события получают только те, кто видит канал. |
| S12 | Средняя | `channel_ack` разбирал идентификатор любой длины как `BigInt`: строка цифр на мегабайт надолго занимала единственный поток сервера; повторять можно дважды в секунду. | Исправлено: идентификатор не длиннее 20 цифр. |
| S13 | Низкая | Строка реакции не ограничивалась по длине (хранилась и рассылалась любая, вплоть до мегабайта); реакцию можно было поставить в канале, которого не видишь. | Исправлено: не длиннее 256 знаков и только при праве просмотра. |
| S14 | Низкая | `POST /api/users/@me/verify-password` не ограничивался по частоте. | Исправлено: тот же порог, что у входа. |
| S15 | Низкая | Вложение без записанного автора мог прикрепить к своему сообщению любой, кто знает его идентификатор. | Исправлено: прикрепить можно только своё. |
| S16 | Инфо | Отключение микрофона и звука модератором и отключение от канала исполняет клиент: сессия LiveKit не разрывается, изменённый клиент остаётся в комнате до конца срока токена (час). | Исправлено для отключения от канала: `bs-server` сам убирает участника из комнаты через API LiveKit (модератор отключил, потеряно право, канал удалён). Отключение микрофона по-прежнему учитывается при выдаче токена. |
| S17 | Инфо | Смена пароля не закрывает открытые соединения WebSocket (токены для REST отзываются). Реплицированному аккаунту текущий пароль при смене не нужен. | Как в оригинале; закрытие соединений рискует разлогинить клиента, который ещё не сохранил новый токен. |
| S18 | Средняя | Предел размера загрузки проверялся только при создании: загрузка с отложенной длиной (`Upload-Defer-Length`) принимала файл любого размера. | Исправлено: предел действует и при объявлении длины позже, и на сам поток данных. |
| S19 | Низкая | `GET /api/uploads/.tus` (каталог вместо файла) отвечал 500 с текстом ошибки файловой системы. | Исправлено: 404. |
| S20 | Средняя | Защита предпросмотра ссылок от обращений во внутреннюю сеть проверяла адрес отдельным запросом DNS, а соединялась по имени заново (подмена ответа DNS между проверкой и соединением); проверялся только первый адрес; адреса IPv6 со вложенным IPv4 (NAT64, 6to4) считались внешними. | Исправлено: имя разрешается один раз, проверяются все адреса, соединение идёт на проверенный адрес, каждый шаг перенаправления проверяется так же. |
| S21 | Низкая | При одобрении заявки на вступление не проверялся бан, выданный после её подачи; заявка уже вступившего участника давала ошибку 500. | Исправлено. |
| S22 | Инфо | Двухфакторной аутентификации у оригинала нет: украденного пароля достаточно для входа. | Добавлено в `bs-server` расширением (TOTP и запасные коды); секрет хранится зашифрованным, код не принимается дважды, неверные коды ограничены по аккаунту. |
| S23 | Средняя | Федерация: адрес пира, названный не администратором (входящий запрос на пиринг, просьба пользователя), проверялся на принадлежность внешней сети отдельным запросом DNS, а соединение шло по имени заново — подмена ответа DNS между проверкой и соединением направляла запрос сервера во внутреннюю сеть. | Исправлено в `bs-server`: имя разрешается один раз, соединение идёт на проверенный адрес; перенаправления не выполняются. |
| S24 | Средняя | Федерация: картинки профиля, значки групп и вложения с пира скачиваются через `safeFetch`, который проверяет адрес одним разрешением имени, а `fetch` разрешает его заново (оригинал сам отмечает это окно). | Исправлено в `bs-server`: имя разрешается один раз, соединение идёт на проверенный адрес, каждое перенаправление проверяется так же; узел по-прежнему должен быть узлом пира, картинки — не больше 8 МБ и только изображения. |
| S25 | Низкая | Федерация: входящее событие применяется несколькими отдельными записями; ошибка посередине (ответ `processing_error`, который отправитель повторит) оставляет событие применённым наполовину. | Исправлено в `bs-server`: каждое событие применяется одной транзакцией и при ошибке откатывается целиком. |
| S26 | Средняя | Вход в копию с паролем, которого копия не знает, отправляет этот пароль на `https://<home_instance>/api/auth/login` обычным `fetch`; `home_instance` берётся из запроса регистрации, так что любой может завести копию, чей «дом» — адрес во внутренней сети сервера, и заставить сервер слать туда запросы. | Исправлено в `bs-server`: запрос идёт через запрос федерации к адресу, который назвал посторонний (только публичные адреса, имя разрешается один раз, без перенаправлений). |

Сохранено в точности как в оригинале: хеши bcrypt (стоимость 12), токены HS256 с теми же
полями (токены и хеши паролей работают на обоих серверах при одном `JWT_SECRET`), отзыв
токенов, выданных до смены пароля, ограничения частоты по адресу за ограниченным числом
доверенных прокси, заголовки безопасности.
