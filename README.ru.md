> [!IMPORTANT]
> **Rustspace — независимый неофициальный проект.** Он не связан с авторами Backspace, не
> одобрен и не поддерживается ими. **Официальный репозиторий Backspace —
> [TheZwiss/backspace](https://github.com/TheZwiss/backspace).** «Backspace» и его логотип —
> товарные знаки Jannis Braun; Rustspace упоминает это имя только чтобы сказать, с чем он
> совместим. О проблемах Rustspace пишите [сюда](https://github.com/QuddyMusic/Rustspace/issues),
> а не в Backspace.

Rustspace целиком написан на Rust. Десктоп-клиент — графический (`egui`/`eframe`, крейт
`bs-app`, бинарник `rustspace`); рядом лежит терминальный клиент `bs-tui` для проверки
протокола. Сервер `bs-server` (бинарник `rustspace-server`) — порт оригинального сервера.

Цель — полная совместимость с оригиналом: клиент работает с неизменёнными инстансами Backspace
(в том числе федеративными) и умеет всё, что умеют веб- и десктоп-клиенты оригинала, а
`bs-server` обслуживает и клиентов оригинала. Чего ещё нет — в [дорожной карте](ROADMAP.ru.md).

## Установка клиента

**Linux, любой дистрибутив — сборка из исходников:**

```sh
curl -fsSL https://raw.githubusercontent.com/QuddyMusic/Rustspace/main/packaging/linux/install.sh | sh
```

Скрипт спросит разрешения поставить пакеты для сборки (pacman, apt, dnf или zypper), при
необходимости Rust через rustup, скачает исходники в `~/.local/src/rustspace`, соберёт клиент и
положит его в `~/.local/bin` с пунктом в меню (`--system` — в `/usr/local`). Голосу и камере
нужен clang 21+; без него клиент соберётся без них и скрипт подскажет, что поставить.
Обновление — тот же запуск ещё раз. Параметры: `--ref v0.3.0`, `--no-voice`, `--uninstall`,
`--help`. Сборке нужно около 10 ГБ места и несколько минут.

Готовые сборки — на [странице релизов](https://github.com/QuddyMusic/Rustspace/releases):

| Система | Как |
|---|---|
| Linux, AppImage | `Rustspace-x86_64.AppImage`: сделать исполняемым и запустить |
| Debian / Ubuntu | `sudo apt install ./rustspace-linux-x86_64.deb` |
| Arch Linux | `sudo pacman -U rustspace-bin-*-x86_64.pkg.tar.zst` или сборка из клонированного репозитория: `cd packaging/arch && makepkg -si` (из релизов ничего не скачивается; `packaging/arch/rustspace-bin` — пакет из готового бинарника) |
| Linux, архив | `rustspace-linux-x86_64.tar.gz` (есть и aarch64): распаковать и запустить `install.sh` или `rustspace` |
| Windows 10 и 11 | `rustspace-setup-x86_64.exe` — ставит для текущего пользователя, без прав администратора; `rustspace-windows-x86_64.zip` — без установки |
| macOS 11+ | `rustspace-macos-aarch64.dmg` (Apple Silicon) или `rustspace-macos-x86_64.dmg` (Intel): перетащить Rustspace в «Программы». Без подписи: первый запуск через «Открыть» в контекстном меню |

**Обновление изнутри.** Когда выходит релиз, сверху появляется полоса с кнопкой «Обновить»:
клиент скачивает файл под свою систему, сверяет его с `.sha256` из релиза, ставит и
предлагает перезапуститься. Так обновляются AppImage, архив и установщик Windows; сборку из
исходников обновляет повторный запуск `install.sh`; пакеты (deb, Arch) обновляет менеджер пакетов — клиент так и скажет.

## Статус

Воркспейс собирается целиком; `cargo clippy --workspace --all-targets --all-features -D warnings`
чист, все тесты зелёные. Совместимость проверяется на настоящем сервере: контрактный стенд
(`cargo xtask contract`) поднимает оригинальный Node-сервер и строго разбирает каждый кадр
WebSocket и каждый REST-ответ, который получает клиент.

### Что умеет GUI

- **Вход.** Логин и регистрация (с приглашением и проверкой имени на лету). Открытый `http`
  вне loopback — только по явному согласию. Сессия переживает перезапуск: токен в системном
  хранилище ключей (Secret Service, Keychain, Credential Manager), запасной путь — файл `0600`.
  В форме — недавние инстансы (щелчок подставляет адрес). Если инстанс при запуске недоступен,
  вход по сохранённой сессии повторяется сам.
- **Несколько аккаунтов.** Меню своей аватарки: другие аккаунты (переключение без пароля) и
  «Добавить аккаунт»; на экране входа — сохранённые аккаунты в один щелчок. У каждого свой
  токен и свои ключи шифрования.
- **Двухфакторная защита** (на сервере с её поддержкой, то есть `bs-server`): код при входе,
  включение, запасные коды и отключение в настройках аккаунта.
- **Ключи доступа (passkey)** (`bs-server`): «Войти по ключу доступа» — подтверждение в браузере
  через Bitwarden, телефон, Windows Hello или связку ключей, без пароля и кода; ключи
  добавляются и удаляются в настройках аккаунта.
- **Сквозное шифрование переписок один на один.** Включается в шапке переписки; текст
  шифруется на устройстве (X25519, XChaCha20-Poly1305) и идёт обычным сообщением, поэтому
  работает через любой сервер, включая оригинальный. Ключи передаются в самой переписке, их
  подлинность сверяется контрольным числом. Вложения шифруются тоже (имя и тип файла — внутри
  зашифрованного текста); не шифруются групповые переписки, прямой секретности нет. Ключ
  лежит в системном хранилище ключей и переносится на другое устройство записью под паролем
  (окно шифрования) или резервной копией на сервере (`bs-server`): её шифрует ключ
  восстановления из 25 знаков, который создаёт устройство и сервер не видит, поэтому взлом
  сервера переписки не раскрывает. Собеседнику нужен этот же клиент —
  веб-клиент оригинала покажет шифротекст. Пока переписка один на один не зашифрована, над ней
  висит тонкая полоса с предупреждением (и с тем, есть ли у собеседника ключ вообще); она
  закрывается одним щелчком и для этой переписки больше не появляется.
- **Пространства.** Каналы и категории, роли и права, переопределения прав каналов, участники,
  баны, приглашения, заявки на вступление, каталог инстанса, настройки уведомлений пространства
  и канала (в том числе отключение на время; колокольчик в шапке канала открывает их).
- **Форматирование и карточки.** Разметка как в веб-клиенте оригинала: заголовки `#`–`###`,
  списки (`-`, `1.`, вложенные отступом), разделители `---`, цитаты `>` и `>>>`, мелкий
  текст `-#`, ссылки `[текст](адрес)`. Кнопка **Aa** у поля ввода открывает панель (жирный,
  курсив, код, спойлер, заголовки, списки, цитата, ссылка) и конструктор **карточек**: блок с
  цветной полосой, заголовком, текстом и картинкой — для правил и объявлений (нужен
  `bs-server`). Превью ссылок и карточки вебхуков видны под сообщениями.
- **Сообщения.** Отправка, правка, удаление, ответы, реакции, упоминания, разметка,
  прочитанность, подгрузка истории, поиск с фильтрами и переходом к найденному. Блоки кода
  подсвечиваются по языку из ограды (` ```bash `, ` ```rust `…; понимаются и псевдонимы Prism). Текст длиннее
  предела сервера (4000 символов) уходит несколькими сообщениями подряд; блок кода на разрыве
  закрывается ` ``` ` и открывается той же оградой (с языком) в следующем сообщении.
- **Файлы и медиа.** Загрузка с прогрессом, миниатюра каждой прикреплённой картинки и
  «Повторить» у неудавшейся загрузки, просмотр картинок, скачивание вложений (одного или всех;
  кнопка **«Загрузки»** в шапке чата показывает их с ходом и миниатюрами, открывает файл
  щелчком и умеет «Показать в папке»), аватарки, баннеры, стикеры и стикерпаки (свои: составить, дополнить, упорядочить;
  чужой открытый пак добавляется из стикера в чате), GIF (поиск Klipy, избранное). Вложение можно спрятать
  под **спойлер** (глаз на прикреплённом файле): картинка размыта, пока по ней не щёлкнут.
  Пометка передаётся приставкой `SPOILER_` к имени файла, как в Discord, поэтому работает с
  любым сервером и через мосты.
- **«Избранное», закреплённые и закладки** (нужен `bs-server`). «Избранное» — чат с самим
  собой для заметок, ссылок и файлов; любое сообщение можно сохранить туда из его меню.
  Закреплённые видны полосой над чатом с миниатюрой фото или видео (щелчок — к сообщению,
  затем к следующему; кнопка рядом — список всех закрепов чата): в беседе один на один — для
  себя или для обоих, в каналах и группах — для всех (с правом «Управлять сообщениями»).
  **Закладки** — единый список со всех чатов и инстансов (на инстансе без закладок, например
  на сервере оригинала, они хранятся на этом устройстве), с поиском,
  группировкой по дате, людям или чатам, фильтром «с медиа» и переходом к оригиналу.
- **Перевод** — только открытые проекты. «Перевести» в меню сообщения или автоперевод чужих
  сообщений не на вашем языке. По умолчанию — на этом компьютере: в *Настройки → Перевод*
  одной кнопкой ставятся llama.cpp (MIT) и открытая модель Qwen (Apache-2.0), на процессоре
  или видеокарте (Vulkan, на macOS — Metal); `llama-server` клиент запускает и гасит сам. Без
  ключей, текст не покидает компьютер. Подходит и свой сервер LibreTranslate или любой сервер
  модели с OpenAI-совместимым API (llama-server, vLLM). Для слабых компьютеров — перевод без
  языковой модели: маленькие модели Firefox Translations (около 30 МБ на направление, только
  процессор, без сети после загрузки) на движке [fxtranslate](https://github.com/gregtatum/translations)
  на Rust (MPL-2.0); язык сообщения определяет whatlang. Код, ссылки и упоминания не
  переводятся и возвращаются как были.
- **Активность (Rich Presence).** Видно, кто во что играет, что слушает и смотрит: строкой
  под именем в списке участников и карточками с обложкой, таймером и прогрессом трека в
  профиле. Клиент сам находит запущенные игры — словарь Backspace, Steam, Flatpak, GOG,
  Heroic, Bottles, Lutris, игры под Wine и Proton, — берёт музыку из любого MPRIS-плеера на
  Linux и держит локальный сервер Rich Presence (`discord-ipc-N`): игры вроде osu!lazer
  сообщают карту, режим и время. Игры можно переименовать, скрыть, упорядочить и добавить
  вручную; их иконки берутся с этого компьютера и загружаются на домашний инстанс
  (`bs-server`). *Настройки → Активность*. Перенесено из PR #482 Backspace (QuddyMusic и
  cirzear), целиком на Rust.
- **NSFW-каналы** (`bs-server`). Канал с такой пометкой в настройках
  (откровенный или шокирующий контент) один раз просит каждого подтвердить, что он готов это
  видеть, прежде чем показать сообщения.
- **Личные сообщения.** Беседы один на один и групповые, друзья и заявки, профили,
  приглашения в пространство карточкой в ЛС. Пересылка сообщений с кликабельным автором — по одному или пачкой до 100, отмеченной галочками;
  настройка «Скрывать профиль при пересылке». Тычки в каналах и «Упомянуть» в меню сообщения. Галерея вложений чата по вкладкам: картинки, видео, аудио, GIF, ссылки, файлы. Свои аватар, баннер и статус для каждого пространства («Мой профиль здесь…» в меню пространства; `bs-server`). Превью трансляции при наведении на голосовой канал или того, кто показывает экран (`bs-server`).
- **Федерация.** Несколько инстансов сразу, чужие — входом через домашний аккаунт. Приглашение
  или запись каталога с ещё не подключённого инстанса подключают его сразу и вступают в
  пространство. В «Обзоре» — общий каталог других инстансов (`/api/directory`), если он
  настроен на домашнем инстансе. Если домашний инстанс теряет связь, личные беседы идут
  через их копии на других ваших инстансах и возвращаются, когда связь восстановится.
- **Голос и видео** (`--features voice`). Голосовые каналы и звонки в ЛС через LiveKit;
  микрофон и звук; громкость микрофона и вывода 0–200 %, громкость каждого участника и
  «заглушить у себя», громкость трансляции и её приглушение, пока кто-то говорит;
  эхо-/шумоподавление и АРУ; проверка микрофона; подсветка говорящих. Камера
  (`--features camera`) и демонстрация экрана со сценой звонка над чатом: захват libwebrtc
  (под Wayland — через портал ScreenCast), 540p–4K или «как есть», 30–120 к/с, VP9 или
  H.264, плавность или чёткость — всё в пределах лимитов трансляций инстанса; системный звук
  без звука самого Backspace (запись по приложениям через PulseAudio/PipeWire на Linux,
  loopback вывода на Windows и macOS). Чужие трансляции и их звук принимаются, только пока
  вы их смотрите, а ведущий видит, кто смотрит. На `bs-server` микрофон идёт с битрейтом
  голоса инстанса (по умолчанию 96 кбит/с); число рядом со звонком на голосовой панели
  понижает его для голосового канала или звонка в ЛС, если связь не тянет.
- **Рабочий стол** (`--features desktop`). Значок в трее: показать/скрыть, микрофон, звук,
  выход; закрытие окна прячет его в трей. Глобальные горячие клавиши (в том числе рация с
  отпусканием) на X11, Windows и macOS, а под Wayland — через портал XDG GlobalShortcuts
  (сочетания назначаются в настройках системы); в окне сочетания работают всегда.
- **Оформление.** Восемь встроенных тем; основная, **«Оксид»**, и **«Оксид светлая»** —
  *стеклянные*: полупрозрачные панели на мягком двухцветном свечении, стеклянные поле ввода,
  меню и окна. Стекло — часть темы: непрозрачность панелей, сила и цвета свечения (с готовыми
  парами) настраиваются во «Внешнем виде» и сохраняются в JSON-файле темы. А ещё свой акцент,
  правка любого цвета, скругление (всё окно собрано из скруглённых модулей, которые ему
  следуют), компактная лента, импорт и экспорт темы в JSON, масштаб, мягкий или *чёткий*
  текст. Звуки интерфейса из оригинала.
  Системные уведомления по правилам оригинала (уровни, отключения, «не беспокоить»,
  упоминания).
- **Языки.** Русский и английский встроены и переключаются на лету; любой другой язык
  добавляется каталогом JSON в `<папка настроек>/locales/<код>.json` (см. «Настройки → Язык»).
- **Страница «Backspace»** в боковой панели, как проектный хаб оригинала: что нового в
  домашнем инстансе (с точкой «обновлено»), ссылки проекта, сообщение об ошибке, версия и
  исходный код этого сервера.
- **Обновления клиента.** «Настройки → О клиенте» проверяет релизы собственного репозитория
  клиента на GitHub (`owner/repo`; значение по умолчанию можно вшить при сборке:
  `BS_UPDATE_REPO=owner/repo`); новая версия скачивается, проверяется и ставится изнутри
  (см. [Установка клиента](#установка-клиента)).
- **Администрирование.** Профиль, смена пароля, удаление аккаунта; панель администратора
  инстанса (настройки, пользователи, хранилище, регистрация, федерация, лимиты трансляций,
  телеметрия, обновления).

Безопасность и известные ограничения — в [AUDIT.md](AUDIT.md).

| `bs-api` | REST-клиент (`/api/*`), Bearer JWT, загрузка и скачивание, ошибки с кодами | 110 |
| `bs-ws` | WebSocket: heartbeat, переподключение, разбор событий | 11 |
| `bs-bot` | Боты на Rust: HTTP API и события, переподключение, короткие действия (см. «Боты») | сквозной в `bs-server` |
| `bs-instances` | Соединение с одним инстансом: диспетчер, переподключение, вход по паролю и токену | 14 |
| `bs-identity` | Логин и регистрация, хранение токенов, учётные данные для чужих инстансов, `UserKey` | 31 |
| `bs-media` | Декодирование картинок и GIF с лимитами размера и пикселей | 13 |
| `bs-voice` | Голос и видео поверх LiveKit: свой звуковой тракт (cpal), микшер, сцена видео, камера, захват экрана, сигналы канала данных | 68 |
| `bs-core` | Состояние и кэш инстанса, применение событий, правила уведомлений | 72 |

## Сборка и запуск

Версия Rust закреплена в `rust-toolchain.toml`, `rustup` подтянет её сам. Возможности (голос,
камера, трей…) выбираются **при сборке**; у самой программы переключателей возможностей нет.

### Сборка

```sh
cargo build --release -p bs-app                                     # GUI без голоса
cargo build --release -p bs-app --features voice,camera,desktop     # всё сразу
cargo build --release -p bs-tui                                     # терминальный клиент
```

В пакете `bs-app` один бинарник — **`rustspace`**, в `bs-tui` — **`bs-tui`**. Release-сборка
лежит в `target/release/` (отладочная, без `--release`, — в `target/debug/`).

### Запуск собранного

```sh
./target/release/rustspace               # Linux и macOS
.\target\release\rustspace.exe           # Windows
./target/release/bs-tui                  # терминальный клиент
./target/release/bs-tui --allow-insecure # bs-tui: разрешить http вне loopback
```

Бинарник самодостаточен: его можно скопировать куда угодно и запустить. Параметров командной
строки у `rustspace` нет, всё настраивается в приложении («Настройки»). Из окружения
читается только `RUST_LOG` для логов, например
`RUST_LOG=rustspace=debug,bs_voice=debug ./target/release/rustspace`. Форма входа спрашивает
адрес инстанса, имя и пароль; для инстанса по `http://` вне loopback поставьте флажок
«Разрешить незащищённое соединение (http)».

Чтобы программа была в `PATH`:

```sh
cargo install --path crates/bs-app --features voice,camera,desktop   # → ~/.cargo/bin/rustspace
rustspace
```

### Собрать и сразу запустить (для разработки)

`cargo run` собирает пакет и запускает его бинарник (`rustspace` у `bs-app`) с теми же
флагами, что вы передали:

```sh
cargo run -p bs-app                                    # отладочная сборка без голоса
cargo run --release -p bs-app --features voice         # оптимизированная, с голосом
cargo run -p bs-tui -- --allow-insecure                # аргументы после `--` идут программе
```

`~/.config/rustspace/` на Linux (учитывается `XDG_CONFIG_HOME`),

`setup.sh --release` видят только опубликованные релизы.

## Сервер (`bs-server`)

Сервер на Rust повторяет оригинальный сервер Backspace: те же маршруты, события WebSocket,
переменные окружения и та же база SQLite. Файл базы оригинала открывается как есть (миграции
те же, уже применённые не повторяются), и обратно — базу, с которой работал `bs-server`,
открывает оригинал. Токены и хеши паролей общие.

**Что перенесено:** регистрация и вход, приглашения; профиль, пароль, удаление аккаунта;
пространства, участники, роли, баны, каналы, категории, переопределения прав; сообщения,
реакции, позиции чтения, «тычки», поиск; личные и групповые переписки; друзья и поиск людей;
настройки уведомлений; голосовые каналы, звонки, модерация голоса, токены LiveKit; загрузка
файлов (tus), раздача, миниатюры, уборка хранилища; предпросмотр ссылок; каталог пространств
и заявки на вступление; стикеры и GIF; админка (пользователи, хранилище, настройки
инстанса); раздача веб-клиента; из федерации — подписи запросов, рукопожатие и ведение пиров
(одобрение, отказ, смена секрета, обнаружение сброса удалённого инстанса), очередь исходящих
событий и их доставка пирам (сообщения, правки, реакции, позиции чтения, группы, дружба,
профиль, присутствие; повторы с паузами, недоступные пиры, отказы получателя), приём
событий от пиров (те же события в обратную сторону, проверка авторства, копии пользователей
других инстансов, скачивание картинок профиля и вложений, удаление копии по запросу её
дома), поиск `user@домен` и заявки в дружбу между инстансами, вход в копию, привязка и
повторная привязка аккаунтов. Каждый
маршрут и каждое событие сверяются с оригиналом сценариями из `tools/compat` — и на SQLite,
и на PostgreSQL.

**Чего нет у оригинала (расширения):** PostgreSQL как хранилище, двухфакторная
аутентификация, справочник ключей сквозного шифрования ЛС. Они не меняют существующие
маршруты: клиент, который о них не знает, работает как раньше. Их таблицы лежат в той же
базе под именами `bs_*`, оригинальный сервер их не замечает.

**Федерация** перенесена и проверена аудитом: события, звонки и «печатает» с пирами ходят в
обе стороны, поиск `user@домен` работает, после простоя пиры догоняют друг друга по журналу
мутаций. Телеметрию сервер не отправляет никогда. См. [ROADMAP.ru.md](ROADMAP.ru.md).

**Отличия от оригинала в мелочах:** миниатюры и стикеры кодируются в WebP без потерь (файлы
крупнее); миниатюры AVIF не делаются; для видео и звука нужны `ffmpeg` и `ffprobe` в `PATH`
(без них файл принимается без длительности и миниатюры — как у оригинала).

### Сборка

```sh
cargo build --release -p bs-server      # target/release/rustspace-server
```

Нужен только компилятор C (SQLite собирается вместе с сервером). Node.js не нужен.

### Установка на сервер (один скрипт)

`packaging/server/setup.sh` ставит, обновляет и переносит сервер на Debian, Ubuntu или
Alpine (systemd или OpenRC), с PostgreSQL и с голосом, видео и стримами через LiveKit.
Без клонирования репозитория (берёт последний релиз):

```sh
curl -fsSL https://raw.githubusercontent.com/QuddyMusic/Rustspace/main/packaging/server/setup.sh \
  | sudo sh -s -- --domain chat.example.org
```

или из клона (собирает сервер из исходников):

```sh
git clone https://github.com/QuddyMusic/Rustspace && cd Rustspace
sudo sh packaging/server/setup.sh --domain chat.example.org
```

Что делает скрипт:

- ставит пакеты и **PostgreSQL**, заводит в нём базу и роль `rustspace` (`--sqlite` — всё в
  SQLite, `--database-url` — внешний PostgreSQL);
- собирает `rustspace-server` из клона, или скачивает из релиза (`--release [ВЕРСИЯ]`) и
  сверяет контрольную сумму, или берёт `--binary`;
- скачивает LiveKit и проверяет его хэш;
- с `--web` ставит **веб-версию** Rustspace (см. ниже);
- пишет `/etc/rustspace/rustspace.env` и `/etc/rustspace/livekit.yaml`, заводит службы
  `rustspace` и `livekit` и проверяет, что обе отвечают;
- **обновляет**: повторный запуск без параметров (после `git pull` или с `--release`)
  сохраняет домен, секреты и данные, а перед заменой сервера снимает дамп базы в
  `/var/backups/rustspace` (хранятся пять последних);
- **переносит**: найденную по дороге базу SQLite — от установки на SQLite, от сервера,
  запущенного вручную (он подхватывается и останавливается), из `--data-from КАТАЛОГ` —
  копирует в `/var/lib/rustspace` и переносит в PostgreSQL командой `rustspace-server
  import-sqlite` одной транзакцией; файл SQLite после этого остаётся как `*.migrated`. Если
  запуск оборвался, следующий продолжит. Установку со старыми именами (`/etc/backspace`,
  `/var/lib/backspace`, служба и пользователь `backspace`) переносит на новые, а старые
  убирает.

**Веб-версия.** Клиент Rustspace работает и в браузере: тот же интерфейс на egui, собранный в
WebAssembly (`packaging/web/build.sh`). `setup.sh --web` ставит его на сервер — скачивает из того
же релиза, что и сервер (`rustspace-web.tar.gz` со сверкой контрольной суммы), а если сервер
собирается из исходников, собирает рядом; Node.js не нужен — и сервер отдаёт его на
`https://ДОМЕН/`. Обновляется вместе с сервером; добавить к работающей установке — так же,
повторным запуском с `--web`, убрать — `--no-web`; при новой установке без `-y` скрипт спросит
сам. Установка, где был веб-клиент оригинала (setup.sh до 0.3.0), при следующем обновлении
получит веб-версию Rustspace. Десктоп-клиент оригинального Backspace — оболочка, которая
открывает страницу инстанса, поэтому он открывает и веб-версию Rustspace: страница вызывает его
`rendererReady`, оставляет сверху полосу в 32 точки, за которую тянется окно без рамки, а кнопки
окна рисует сам клиент. В браузере настройки, аккаунты и ключи шифрования хранятся в
`localStorage` страницы, скачанное уходит в загрузки браузера, уведомления — уведомления
браузера. Голосовые каналы и звонки работают и в браузере: свой небольшой клиент LiveKit поверх
WebRTC браузера (сигнализация — `livekit-protocol`), микрофон выбирается в настройках сайта в
браузере; камера, показ экрана, трей, игровая активность, локальные модели и самообновление
есть только на десктопе. Файлы выбираются окном выбора файлов браузера или перетаскиваются на страницу. Модуль отдаётся сжатым gzip, если браузер его
понимает, и сверяется по ETag: повторное открытие не скачивает его заново.

Рассчитан на обратный прокси впереди (Nginx Proxy Manager, Caddy…): в конце печатает, что
настроить в нём и на роутере — `https://ДОМЕН` → порт 3000, `https://lk.ДОМЕН` → порт 7880
(оба с WebSocket), TCP 7881 и UDP 7882 — проброс на машину. Все параметры — `--help`.

### Запуск

```sh
JWT_SECRET="$(openssl rand -hex 32)" \
DB_PATH=data/rustspace.db UPLOAD_DIR=data/uploads \
target/release/rustspace-server
```

Сервер слушает `0.0.0.0:3000`. Первый зарегистрированный пользователь становится
администратором. Останавливается по `Ctrl+C` или `SIGTERM`, дожидаясь открытых запросов.

Перейти с оригинального сервера: остановите его, сделайте копию базы и запустите
`rustspace-server` с теми же `JWT_SECRET`, `DB_PATH` и `UPLOAD_DIR`. Вернуться — так же в
обратную сторону.

Чтобы сервер отдавал и веб-версию, запустите `setup.sh --web` или соберите её сами
(`packaging/web/build.sh КАТАЛОГ`) и укажите каталог сборки: `BS_WEB_DIST=КАТАЛОГ`. Без него на `/` открывается
короткая страница: подключаться к инстансу нужно десктоп-клиентом Rustspace, вот адрес для
копирования и ссылкой на исходники и сборки (`BACKSPACE_SOURCE_URL`, по умолчанию — этот
репозиторий; если меняли сервер, укажите свой). Страница по-русски для браузеров, которые
предпочитают русский, и по-английски для остальных (`?lang=ru|en` переключает). Значок на ней —
`packaging/brand/rustspace/icon.svg`; остальные варианты и их генератор лежат рядом.

### PostgreSQL

```sh
createdb -T template0 -E UTF8 --lc-collate=C --lc-ctype=C backspace
DATABASE_URL=postgres://user:password@127.0.0.1/rustspace JWT_SECRET=… target/release/rustspace-server
```

Схему сервер создаёт и дополняет сам: она выводится из миграций оригинала. Сортировка `C`
нужна, чтобы порядок и сравнение строк совпадали с SQLite. Перенести данные из файла SQLite
(оригинального сервера или `bs-server`) в пустую базу PostgreSQL:

```sh
DATABASE_URL=postgres://… JWT_SECRET=… target/release/rustspace-server import-sqlite data/rustspace.db
```

Перенос идёт одной транзакцией: либо всё, либо ничего. Обратного переноса нет. TLS к
PostgreSQL задаётся, как у libpq, параметром `sslmode` в адресе: `disable`; `prefer` (по
умолчанию: шифрование, если сервер его предлагает, сертификат не проверяется); `require`
(только с шифрованием; сертификат проверяется, если задан `sslrootcert`); `verify-ca` (цепочка
до доверенного центра); `verify-full` (цепочка и имя узла). `sslrootcert` — файл PEM с
центрами или `system`; без него `verify-*` доверяют системным корням. Через сеть —
`verify-full`:

```sh
DATABASE_URL='postgres://user:password@db.example/backspace?sslmode=verify-full&sslrootcert=/etc/ssl/db-ca.pem'
```

Сервер работает с базой через одно соединение: транзакции идут по очереди, как у SQLite.

### Двухфакторная аутентификация

Пользователь включает её сам в настройках аккаунта (клиент на Rust) или запросами
`/api/auth/2fa`: `setup` (пароль) выдаёт секрет для приложения-аутентификатора, `enable`
(код) включает защиту и возвращает десять запасных кодов. После этого вход требует поле
`totp` или `recoveryCode`; без него сервер отвечает `401` с кодом `two_factor_required`.
Секрет хранится зашифрованным ключом, производным от `JWT_SECRET`: при смене `JWT_SECRET`
защиту придётся настроить заново. Потерявшему и телефон, и запасные коды доступ возвращает
администратор: сброс пароля в админке снимает и второй фактор.

Ключи доступа (passkey, WebAuthn) — `/api/rustspace/passkeys`: клиент получает билет и
открывает страницу инстанса `/rustspace/passkey/<билет>`, где браузер создаёт ключ или входит по
нему; клиент сверяет код и забирает токен. Подписи ES256, EdDSA и RS256 проверяются без
сторонних библиотек. Адрес сайта — `PUBLIC_ORIGIN`, а без него `https://DOMAIN`; нужно доменное имя (браузеры не принимают IP-адрес как
источник WebAuthn) и HTTPS вне `localhost`.

### Мосты в Telegram, Discord и Matrix

*(bs-server)* Текстовый канал можно связать с группой Telegram, каналом Discord или комнатой
Matrix: сообщения канала уходят туда, а оттуда приходят в канал. Люди из другой сети видны
как отдельные пользователи с подписью вроде «Anna · Telegram»; войти под ними нельзя. Файлы
уходят ссылками на сервер.

1. Создайте бота и впишите его токен в `/etc/rustspace/rustspace.env`, затем перезапустите
   сервер (`systemctl restart rustspace` или `rc-service rustspace restart`). Установщик
   сохраняет эти переменные при обновлениях.
   - **Telegram**: создайте бота у @BotFather, задайте `TELEGRAM_BOT_TOKEN`. Выключите
     privacy mode (`/setprivacy` → Disable), иначе бот видит только команды.
   - **Discord**: создайте приложение на discord.com/developers, добавьте бота, включите
     *Message Content Intent*, задайте `DISCORD_BOT_TOKEN`. Пригласите бота с правами видеть
     каналы, отправлять сообщения и *Управлять вебхуками* (через вебхук Discord показывает
     имя автора, а не бота).
   - **Matrix**: зарегистрируйте боту аккаунт, задайте `MATRIX_HOMESERVER`
     (`https://matrix.org`) и `MATRIX_ACCESS_TOKEN` (Element: Настройки → Помощь и о
     программе → Токен доступа). Зашифрованные комнаты не поддерживаются.
2. Добавьте бота в чат и отправьте `/rustspace_id` (Telegram) или `!rustspace_id` (Discord,
   Matrix) — он ответит ID чата. В комнату Matrix бот входит сам по приглашению.
3. В Rust-клиенте откройте настройки канала → **Мосты**, выберите сеть и вставьте ID. Нужно
   право «Управлять каналами».

`TELEGRAM_API_URL` и `DISCORD_API_URL` меняют адрес API (свой Bot API сервер, тесты).

**Telegram заблокирован у хостера.** Задайте прокси в `TELEGRAM_PROXY` (или
`setup.sh --telegram-proxy URL`):

- **MTProto-прокси в локальной сети**, например
  [tg-ws-proxy-rs](https://github.com/valnesfjord/tg-ws-proxy-rs) (MIT) на роутере, который ведёт
  Telegram через WebSocket: вставьте ссылку, которую он печатает при запуске, —
  `TELEGRAM_PROXY='tg://proxy?server=192.168.1.1&port=1443&secret=dd…'` (подходят и
  `https://t.me/proxy?…`). Мост поднимает у себя крошечный SOCKS5 на 127.0.0.1 и говорит с
  прокси по протоколу obfuscated2 с его секретом. Секреты fake-TLS (`ee…`) не поддерживаются.
  Работает для личных мостов: Bot API — это HTTPS, через MTProto-прокси он не ходит.
- **SOCKS5** `socks5://хост:порт` (можно `socks5://логин:пароль@хост:порт`) — и для моста через
  бота, и для личных. У tg-ws-proxy есть и такой вход: `--socks-enabled --socks-host 0.0.0.0`,
  тогда `TELEGRAM_PROXY=socks5://роутер:1080`, но Bot API через него не пойдёт (он только для
  MTProto). Для бота нужен обычный SOCKS5 с выходом наружу — например,
  [shadowsocks-rust](https://github.com/shadowsocks/shadowsocks-rust): `ssserver` на VPS за
  границей и `sslocal -b 0.0.0.0:1080 …` в соседнем контейнере.

Если Telegram не ответил за 25 секунд, вход в личный мост сообщает об этом, а не обрывается
сетевой ошибкой.

### Личные мосты: свои аккаунты Matrix и Telegram в ЛС

*(bs-server)* Кроме мостов каналов, каждый может подключить **свой** аккаунт: в клиенте
Настройки → **Мосты**. Затем выберите чаты — каждый станет личной
перепиской с собеседником вида «Анна · Telegram»: его сообщения приходят от него, ваши ответы
уходят в чат от вашего аккаунта, а написанное вами с телефона тоже появляется в переписке.
В групповых чатах перед текстом стоит имя автора.

- **Matrix** — адрес сервера и токен доступа (Element: Настройки → Помощь и о программе) или
  логин и пароль. Зашифрованные комнаты не поддерживаются.
- **Telegram** — вход по номеру и коду, при включённой двухэтапной проверке — с облачным
  паролем. Нужны API ID и API hash приложения с [my.telegram.org](https://my.telegram.org):
  одни на весь сервер — администратор задаёт их при установке (`setup.sh --telegram-app
  ID:HASH`, это `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в `rustspace.env`). Выпуски можно
  собрать с ключами по умолчанию: секреты CI `RUSTSPACE_TELEGRAM_API_ID` и
  `RUSTSPACE_TELEGRAM_API_HASH` вшиваются в `rustspace-server`, и тогда настраивать ничего не
  нужно. Если ключей нет нигде, каждый вводит свои при входе. Клиент MTProto — [grammers](https://github.com/Lonami/grammers)
  (MIT/Apache-2.0, Lonami и участники).
- **Discord** личные аккаунты не подключает: вход под ними нарушает правила Discord.

Ключи (токен Matrix, ключи сессии Telegram) хранятся в базе сервера зашифрованными ключом из
`JWT_SECRET`; сервер видит переписку в подключённых чатах, поэтому подключайте аккаунт только
на инстансе, которому доверяете. Отключить аккаунт — там же, ключи удаляются. Выключить личные
мосты на сервере: `PERSONAL_BRIDGES=off`.

### Вебхуки и карточки

*(bs-server)* Настройки канала → **Вебхуки** создают адрес, по которому внешняя программа
пишет в канал без входа: CI, мониторинг, RSS, свой бот. Тело — как у Discord (`content`,
`username`, `avatar_url`, `embeds` с заголовком, текстом, цветом, полями, подписью и
картинкой), так что готовые интеграции работают, если подставить адрес:

```sh
curl -H 'Content-Type: application/json' \
  -d '{"content":"Сборка **прошла**","embeds":[{"title":"main","color":3066993}]}' \
  https://ваш.домен/api/webhooks/ID/TOKEN
```

`?wait=true` возвращает созданное сообщение. Адрес — секрет: утёк — удалите вебхук. Нужно
право «Управлять каналами». Карточки хранятся как обычные встраивания, поэтому заголовок и
текст видит и веб-клиент оригинала.

### Боты

*(bs-server)* Настройки → **Для разработчиков** → «Режим разработчика» → **Боты** создают бота: участника, за которого пишет ваша программа,
со своим токеном и меткой **БОТ**. Добавьте его в пространство, где у вас есть «Управление
пространством», и запустите программу с токеном. Боты пользуются тем же HTTP API и событиями
WebSocket, что и клиенты (`Authorization: Bot rsb_…`), поэтому их пишут на любом языке: для
Rust есть крейт `bs-bot`, на JavaScript и TypeScript хватает `fetch` и `WebSocket`. К учётным
записям, друзьям, другим ботам и API администратора у ботов доступа нет. Подробности и примеры
— [docs/bots.ru.md](docs/bots.ru.md).

### Активность и иконки игр

*(bs-server)* У активности может быть `playback` (`positionMs`, `durationMs`) — позиция трека,
не зависящая ни от чьих часов; сервер сам сдвигает её, пока хранит активность, и поздний `ready`
видит текущий момент. Активность снимается, как только закрывается опубликовавшее её
соединение (настольный клиент вышел, вкладка браузера осталась), а снять её можно и внутри
3-секундного ограничителя. `POST /api/game-icons` принимает PNG, JPEG или WebP в base64 (до
512 КБ), хранит WebP 256 точек и отдаёт ссылку; иконку, которую никто не загружал год,
уборка удаляет. Перенесено из PR #482 Backspace.

### Обновление сервера из клиента

*(bs-server и `setup.sh`)* В *Настройки → Обновления* у администратора инстанса есть кнопка
**«Обновить сервер»**. Сам сервер root-прав не получает и ничего не качает: он только кладёт
заявку в `/var/lib/rustspace/updater`. Дальше работает root-помощник, которого ставит
`setup.sh` (`/usr/local/lib/rustspace/rustspace-update.sh`; запускается `rustspace-update.path`
в systemd или службой `rustspace-updater` в OpenRC):

1. берёт выпуск только из репозитория, заданного при установке (`GITHUB_REPO`), а не из
   заявки, и сверяет опубликованную SHA-256;
2. останавливает сервер и копирует базу и прежний файл сервера в `/var/backups/rustspace`
   (если копия не получилась — ничего не меняет);
3. запускает новую версию и минуту ждёт, что она ответит новым номером; иначе возвращает
   прежний файл и базу.

Клиент показывает каждый шаг. `setup.sh --no-updater` — без помощника.

Там же, пока раздел открыт (иначе ничего не опрашивается), — состояние сервера: процессор,
память, нагрузка, сколько в сети, размер базы, все диски со свободным местом и тем, что на
них лежит, и резервные копии с размерами. Помощник принимает и другие заявки
(`job-request.json`): копия сейчас (база без остановки сервера, по желанию с файлами
пользователей), удаление копии, другой каталог для копий и — из *Настройки → Хранилище* —
перенос файлов пользователей на другой диск (сервер останавливается на время копирования;
прежние файлы удаляются только после успешного запуска, иначе всё возвращается). Сетевые
хранилища (NFS, SMB, WebDAV) монтируются в системе, например через `/etc/fstab`, — клиент
только выбирает точку монтирования. Помощник заново проверяет каждый путь и создаёт только
свои каталоги `rustspace-backups` / `rustspace-uploads`. Повторный `setup.sh` сохраняет
выбранные каталоги.

### «Избранное», закреплённые, закладки и NSFW

*(bs-server)* Дополнения к API оригинала (`/api/rustspace/…`; закладки на `/api/bookmarks`
повторяют API, предложенный для оригинала в PR #474); клиенты оригинала их просто не видят. «Избранное» —
групповая ЛС, где участник только владелец, поэтому веб-клиент оригинала показывает её как
обычную группу. Закреплённые хранятся в `bs_pins` (область `me` или `all`), закладки — в
`bs_bookmarks`, пометка NSFW — в `bs_channel_flags` и в объекте канала как `nsfw`. События:
`rs_pins_updated`, `bookmark_added`, `bookmark_removed`.

### Битрейт голоса

*(bs-server)* Оригинал публикует микрофон с битрейтом LiveKit по умолчанию. Здесь его задаёт
администратор инстанса в «Настройки → Стриминг → Голос в звонках» (16–510 кбит/с, по
умолчанию 96); управляющий голосовым каналом и оба собеседника в звонке ЛС могут понизить его
для своего звонка, если связь плохая. Клиент применяет изменение на лету.

### Проверка совместимости

`tools/compat` поднимает оригинальный сервер и `bs-server` на копии одной базы и выполняет
на обоих одинаковые сценарии, сравнивая ответы и события WebSocket:

```sh
tools/compat/up.sh                    # нужен checkout Backspace с `pnpm install`
python3 tools/compat/s_spaces.py      # и s_channels, s_messages, s_dm, s_social, s_account,
                                      # s_voice, s_admin, s_search, s_files, s_embeds,
                                      # s_stickers, s_gif, s_explore, s_directory,
                                      # s_adminusers, s_bodies; cmp_ready.py
python3 tools/compat/t_twofactor.py   # расширения bs-server: двухфакторка
python3 tools/compat/t_e2ee.py        # и справочник ключей
BS_E2EE_LIVE_A=https://x1.test BS_E2EE_LIVE_B=https://y1.test BS_E2EE_LIVE_CA=/tmp/fedca/ca.pem \
  cargo test -p bs-app e2ee_live -- --ignored   # два клиента через федерацию (свежий стенд fed_up.sh)
```

Путь к checkout задаётся переменной `ORIG` (см. начало `up.sh`). Тот же прогон с
`bs-server` на PostgreSQL: `BS_STAND_PG=postgres://user@host:port tools/compat/up.sh` — база
`bs_stand` создаётся заново и заполняется из той же копии SQLite.

Федерация проверяется отдельным стендом из двух пар инстансов: оригинал ↔ оригинал и
`bs-server` ↔ оригинал (с `BS_FED_RUST_Y=1` — `bs-server` с обеих сторон, с
`BS_FED_PG=postgres://…` — `bs-server` на PostgreSQL). Один и тот же сценарий идёт по обеим
парам; ответы, строки в базах (пиры, очередь исходящих, журнал мутаций), то, что получил
второй инстанс, что принял первый (копии пользователей, журнал применённых событий, очередь
файлов), и события сравниваются. Федерация оригинала адресует инстанс именем узла без
порта, поэтому инстансы видят друг друга по https под именами `x1.test`, `y1.test`,
`x2.test`, `y2.test`: `fed_up.sh` прописывает их в `/etc/hosts`, выпускает тестовый
удостоверяющий центр и поднимает TLS-фронт `tls_front.py` на порту 443 (нужны права root).

```sh
tools/compat/fed_up.sh                # инстансы на портах 3111–3114, базы с нуля
python3 tools/compat/f_peering.py peering    # каждый сценарий — на свежем стенде
tools/compat/fed_up.sh && python3 tools/compat/f_peering.py approvals
tools/compat/fed_up.sh && python3 tools/compat/f_outbox.py delivery
FEDERATION_BACKOFF_DIVISOR=100000 tools/compat/fed_up.sh && python3 tools/compat/f_outbox.py retries
tools/compat/fed_up.sh && python3 tools/compat/f_inbound.py inbound relay_checks
tools/compat/fed_up.sh && python3 tools/compat/f_lookup.py friends accounts
BS_FED_TEST_ROUTES=1 FEDERATION_BACKOFF_DIVISOR=1 tools/compat/fed_up.sh && python3 tools/compat/f_sync.py pull serve pages
BS_FED_LIVEKIT=1 tools/compat/fed_up.sh && python3 tools/compat/f_calls.py one_on_one group
```

## Переводы

Ключи строк — русский исходный текст (как в gettext). Английский каталог —
`crates/bs-app/locales/en.json`; тест падает, если у строки в коде нет английского перевода,
а подстановки (`{name}`) обязаны совпадать. Чтобы добавить язык, скопируйте `en.json`,
впишите в `"@language"` название языка на нём самом, переведите значения и положите файл в
`<папка настроек>/locales/<код>.json` — язык сразу появится в «Настройки → Язык».

## Правила

- `unsafe_code = "deny"` во всём воркспейсе (в `bs-voice` — `forbid`).
- `.unwrap()`, `.expect()`, `panic!()`, `todo!()` запрещены в рабочем коде (clippy deny).
- Ошибки: `thiserror` в библиотеках, `anyhow` в приложении.
- Права — `bitflags` над `u64`, сериализуются строкой (JSON теряет биты выше 2^53).
  Snowflake-идентификаторы — строки. `Origin` — enum `{Home, Remote(Url)}`.
